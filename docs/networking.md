# Сеть (Photon Fusion)

## Тариф
- Free: 100 CCU для коммерческих игр. Платные: 500 CCU $95/мес, 1000 CCU $185/мес, Premium Cloud usage-based до 50 000 CCU.
- Burst-защита включается только с тарифа 500 CCU и выше; на free нет. Мониторить график CCU и апгрейдить заранее.
- **Риск для демо:** популярное демо на Next Fest может упереться в лимит 100 CCU. Уточнить у Photon, как считаются демо, и подготовить апгрейд.

## Модель (решено: Fusion Host Mode)
- **Fusion 2, режим Host** (`NetworkRunner.StartGame` с `GameMode.Host`). Создатель лобби — хост: и игрок, и сервер одновременно. Остальные — клиенты (`GameMode.Client`) подключаются по коду сессии или из списка сессий (Photon Lobby/Session List — публичные лобби).
- **Почему Host, а не Shared Mode:** авторитет должен быть один и явный (HP, поимка, кто вселился в какой предмет), это проще для анти-чит логики, чем Shared Mode, где авторитет размазан по клиентам. Host хорошо ложится на «настройки меняет только создатель».
- **Минусы, которые нужно заложить в код:** у хоста преимущество по задержке (его ввод не идёт по сети); если хост выходит, матч обычно завершается, если не настроена миграция хоста — на MVP миграцию не делаем, при выходе хоста матч завершается с сообщением, это ограничение записать в `demo-scope.md`.
- **Выход хоста (решено, разделено по фазам):**
  - **В лобби (до старта игры):** матч завершается для всех, лобби распускается.
  - **Во время матча:** цель — **миграция хоста** через встроенный Fusion **Host Migration API** (официальный пример: Fusion Host Migration Sample), кроме одного случая: если вышедший хост был **единственным охотником** в матче — игра завершается, а не мигрирует. Если охотников несколько или хост был прячущимся — миграция происходит, матч продолжается на новом хосте.
  - **Сложность:** нетривиальная отдельная система (снимок состояния сетевых объектов у старого хоста, восстановление у нового), задача для Opus, тестируется отдельно от геймплея (нужно симулировать реальный обрыв хоста).
  - **Приоритет:** не входит в MVP и не обязательна для демо Next Fest. Делается после подтверждения, что играть весело, и по остатку времени до февраля (решение по срокам — после контрольной точки 15 ноября, `roadmap.md`).
- **Первая задача по сети (Opus):** пустой NetworkRunner, подключение 2-4 клиентов в одну сессию, синхронизация позиции игрока. Это и есть цель контрольной точки 15 ноября.
- Публичные/приватные лобби: публичные через список сессий Fusion (`SessionInfo`, видимые в `NetworkRunner.SessionList`), приватные — подключение по коду комнаты (`SessionName`), не показывать в общем списке.

## Задачи повышенной сложности (Opus)
- Серверная авторизация состояния, RPC-архитектура.
- Race condition: два игрока вселяются в один предмет.
- Синхронизация ragdoll и импульса пинка.
- Избирательная рассылка звуковых событий (звук повторного превращения только прячущимся).
- Отладка десинхронизации и репликации.
- Анти-чит логика.
- Расширение для Twitch (если будет делаться, `parked.md`).

## Тестирование
Мультиплеер проверять несколькими клиентами; на 8 ГБ ОЗУ это тяжело (`business.md`).
Частоту синхронизации не завышать, лишние данные не слать.
