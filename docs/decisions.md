# Журнал решений (коротко: что и почему)

- Вселение в существующий предмет, а не создание копии: убирает проблему лишнего дубликата и заучивания количества предметов.
- Превращение без лимита, но с кулдауном ~12 сек: не позволяет менять облик бесконечно часто (штраф охотника за промах позже убран полностью, так что кулдаун превращения — самостоятельная цифра, не связанная с ним).
- Требование разрыва линии видимости для превращения не используется: способность и так теряет ценность на глазах охотника.
- Уязвимость во время холда E: иначе это способ переждать атаку.
- Дробовик, затухание урона до жёсткого предела 0: заставляет сближаться.
- Штраф только за промах, без патронов: избегаем «последней пули» и выключения охотника из раунда.
- Потеря HP охотника за попадание по настоящим предметам не вводится (решение принято, когда ещё был штраф за промах — штраф позже убран, вопрос можно пересмотреть при необходимости).
- Автонаводки нет: на PC с мышью она обесценивает навык.
- Без иконки над головой у маячка, только звук: сохраняет стелс.
- Один звук маячка: клоунский нос «кряк-кряк».
- Без физики разрушения предмета при поимке: избыточно.
- Общий эффект «пуфф» для поимки и повторного превращения: звук повторного превращения слышат только прячущиеся.
- Ручной вызов клоунского звука разрешён: даёт блеф и клипы.
- Таран и пинок как фирменная фишка: ни в одном крупном Prop Hunt прячущиеся не могут ответить физически.
- Unity, не Unreal: Blueprint плохо поддаётся генерации ИИ.
- Настройки лобби меняет только создатель, через комнату с указкой: клипабельно и просто по правам.
- Автопревращение опоздавшего в ближайший свободный предмет, с мгновенной сменой камеры.
- Процедурное движение предметов вместо готовых анимаций: работает на любом предмете без риггинга.
- Штраф за промах плоский 5 сек: прежние 15 сек слишком жёсткие для мелких целей. (История: позже штраф убран полностью, см. ниже.)
- Свист near-miss слышит только задетый прячущийся, в пределах эффективной дальности дробовика.
- Превращение обычным нажатием E, без удержания: игрок должен быстро менять предмет при побеге.
- Выбор предмета белой точкой по центру с локальной обводкой (видит только наводящий игрок).
- Ускорение отдельной кнопкой с шлейфом пыли и кольцевой шкалой в HUD.
- Таран работает только во время ускорения; отдельного кулдауна тарана нет — ограничители это шкала ускорения и окно неуязвимости охотника. Кулдаун повторного превращения (~12 сек) при этом остаётся отдельно.
- Шлейф пыли ускорения виден всем, включая охотника.
- Ускорение включается только при полной шкале: защита от спама короткими ускорениями и цепочки таранов.
- Стиль мира по референсу Gamble With Your Friends (картинка, цвет, свет), без копирования его персонажей и мотивов; освещённый шейдер + запечённый свет вместо чистого unlit.
- Окружение Meccha Chameleon фотореалистичное, поэтому её стиль окружения не берём, только идею нейтральных персонажей.
- Освещение без глубоких чёрных теней (мягкие цветные тени, высокий ambient): иначе теряется игра на несоответствиях.
- Все вселяемые предметы освещаются одинаково (Light Probes), lightmaps только для статичной архитектуры: освещение не должно выдавать игрока.
- Палитра подтверждена; меняется только картинка, не геймплей и не персонажи.
- Unity 6.3 LTS (не tech stream): два года поддержки важнее последних фич для многомесячного проекта.
- Fusion Host Mode: единый явный авторитет проще для анти-чит и совпадает с моделью лобби.
- Миграция хоста не делается в MVP: при выходе хоста матч завершается.
- Апгрейд ОЗУ не делаем, тестируем мультиплеер малыми группами клиентов.
- Пока работаем только на подписке Claude Pro, без API-ключа Opus.
- Порядок разработки: сначала MVP с ботами на серой карте, стиль и полный объём демо после подтверждения, что играть весело.
- MCP-плагин для Unity: MCP for Unity (CoplayDev).
- Near-miss свист остаётся в игре.
- Выход хоста: в лобби — завершение; в матче — миграция хоста через Fusion Host Migration API, кроме случая «хост был единственным охотником» (тогда завершение). Не входит в MVP/демо.
- Прыжок без анимации и риггинга у обеих ролей, компенсируется squash-and-stretch и толчком камеры; без звука отрыва, со звуком приземления; пыль при приземлении отложена.
- Ragdoll охотника: упрощённый риг 6-8 физических тел, финально (не временная оптимизация) — точность падения не важна, важна только клипабельность/смешность.
- Лимит одновременных ragdoll: 3 (страховка, не обычный режим — таран и так редкое событие из-за требования полной шкалы ускорения).
- Пониженная частота тика у ботов-прячущихся вдали от охотника: чисто оптимизация, не влияет на их поведение/интересность.
- Тени и освещение единые для всех предметов (занятых и свободных): никакой дифференциации по качеству, чтобы не выдавать игрока.
- Tripo используется и для крупной мебели (стеллажи, касса, холодильник), не только для предметов пряток — он хорошо держит форму отдельных объектов; примитивами остаётся только капитальная оболочка помещения.
- Правило Tripo: один промпт = один объект, паки не генерировать (риск слипшегося меша).
- Подключение Tripo к Claude Code через MCP пока не делаем (alpha, риск бесконтрольного расхода кредитов); работаем вручную через сайт.
- Пинок: реальная физика даёт хаотичный кувырок/отскок бесплатно; после конца оглушения добавлена процедурная фаза самовыравнивания (Slerp к вертикали + коррекция позиции), а не мгновенный снап к идеальной позе.
- Палитра больше не фиксирована конкретными hex-цветами: важна узнаваемость реального супермаркета, а не конкретная гамма — правила освещения и шейдер остаются в силе отдельно от цвета.
- Размер карты 20×14 м (~280 м²) — небольшой продуктовый, баланс играбельности с размером (маячок и число игроков не рассчитаны на большую площадь).
- Во время ускорения обычная процедурная анимация движения предмета («прыг-скок») отключается — предмет вместо этого гладко скользит, со шлейфом пыли; отдельное узнаваемое визуальное состояние.
- Живые 2D-лица на предметах повышены из запасного варианта до полноценной второй фирменной фишки (`systems/faces.md`): базовое выражение — смена текстуры по событиям, зрачки — процедурное движение кодом (гугли-глаза), работает одинаково у занятых и пустых предметов (иначе утечка информации).
- Лицевая реакция НЕ привязывается к near-miss: это раскрыло бы охотнику скрытую информацию, которая по замыслу должна быть видна только задетому прячущемуся.
- Лицо предмета не просто меняет текстуру, а физически доворачивается навстречу охотнику (ограниченный угол, Slerp-плавность) — эффект "предмет приподнимается и смотрит"; зрачки — дополнительная докрутка поверх этого, не единственный механизм.
- Оглушение после пинка получило промежуточную фазу "в отключке" (после физического кувырка, до самовыравнивания): звёздочки над головой (вращающиеся 2D-спрайты, прикреплены к предмету), синхронно с выражением "оглушён" на лице. Дрожание лица влево-вправо рассматривалось и отклонено как лишнее.
- Исправлена ошибочная модель повторного превращения: игрок НЕ телепортируется к другому экземпляру предмета (тот не трогается и не резервируется), а копирует его внешний вид на своём текущем месте. Логика резервирования предмета (PossessionAuthority) применяется только к самому первому вселению на старте, не к сменам во время охоты.
- Проверка столкновений для камеры от третьего лица добавлена как требование (ранее отсутствовала, камера могла видеть сквозь стены/за карту).
- Зазор предмет-на-предмете при динамическом прыжке игрока НЕ подтверждён как решённый — замеры Claude Code проверяли только статичную геометрию уровня, не контакт с другим предметом; требуется отдельная проверка.
- Штраф за промах убран полностью — перезарядка после промаха и после попадания одинаковая (~1,2 сек).
- Боты: боковое виляние при побеге сохраняется и в воздухе во время прыжка — осознанное решение владельца проекта (усложняет попадание, делает бота живее), заменяет прежнее требование ограничивать виляние в воздухе (2026-10-04, `systems/bots.md`).
