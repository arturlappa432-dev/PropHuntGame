# Карта: ресторан (основная карта демо)

**Решено (2026-10-07):** основная карта демо — ресторан, а не супермаркет. Супермаркет остаётся серой тестовой картой для проверки механик и ботов (`map-supermarket.md`).

**Почему ресторан:** свежее супермаркета (частый сеттинг Prop Hunt), больше разнообразия зон и смешных предметов для клипов (еда, посуда, кухонная утварь, падающие при таране вещи). Минус: меньше длинных рядов одинакового, поэтому «гнёзда» однотипных предметов нужно закладывать в планировку намеренно (ниже).

- Одна карта, вручную (не процедурная). Реиграбельность даёт рандомизация предметов (`systems/spawn.md`).
- Предметов больше, чем игроков.
- Не просто мебель, а **тематические зоны спавна** с привязанной темой и сеткой точек.
- Карта замкнута: ни одного проёма в пустоту (двери входа, окна — закрытые). На тестовой карте открытый вход уже ронял игроков и ботов с карты.

## Требования игры к планировке (решено)
1. **Гнёзда однотипных предметов** — основа «замри среди таких же»: сервированные столы (тарелки, стаканы, приборы), стулья у столов, бутылки за баром, кастрюли и сковороды на кухне, ящики и банки на складе.
2. **Вертикаль:** поверхности на разной высоте (барные полки, кухонные и складские стеллажи, столы, стойки), чтобы мелкие предметы прятались не только на полу. Боты уже умеют прыгать на полки любой высоты (`systems/bots.md`).
3. **Проходы шире тела охотника и ботов**, без тупиков на виду; несколько путей между зонами для побега.
4. **Без тёмных углов** (`art-and-audio.md`, правила освещения): ресторан тёплый, но светлый.

## Зоны (предложено, уточнить при серой планировке)
- **Обеденный зал** — столы со стульями, часть сервирована; диваны или кабинки у стены.
- **Бар** — стойка, стулья, полки с бутылками и стаканами за стойкой.
- **Кухня** — рабочие столы, плиты, полки с посудой и кастрюлями, мойка.
- **Склад / кладовая** — стеллажи с ящиками, мешками, банками.
- **Вход и гардероб / касса** — стойка администратора, вешалки, растения.

**Размер (предложено):** как у тестовой карты, ~20×14 м (~280 м²) — тот же баланс с радиусом маячка 14–15 м (`systems/beacon.md`) при 4–10 игроках. Подтвердить на серой планировке. Открытые вопросы — `open-questions.md`.

## Порядок работы (перенесено с супермаркета, решено)
1. **Серая планировка:** зоны из примитивов, Editor-скриптом по параметрам (`CLAUDE.md`, правило 6), без запечённого света. Цель — проверить проходимость, укрытия и ботов, не красоту.
2. **Тестовая комната** (`style-test-room.md`) — шейдер, свет, bloom на нескольких объектах, сравнение с референсом.
3. **Крупная мебель через Tripo:** столы, стулья, барная стойка, плиты, стеллажи — по одному объекту на промпт (`art-pipeline.md`).
4. **Капитальная оболочка** (стены, пол, потолок, проёмы, окна) — из примитивов кодом с фасками и молдингами (ниже): Tripo плохо держит большие плоские интерьерные формы.
5. **Мелкие предметы для маскировки:** CC0-наборы + точечно Tripo, каждый предмет отдельным промптом.
6. Сетки точек и пулы через Editor-скрипт.
7. Свет запекать (baked), не realtime; тёплые источники по зонам, emissive на вывесках, лампах, витрине бара.

**Подключение Tripo к Claude Code через MCP (решено: пока нет).** Официальный Tripo MCP — альфа, требует параллельно Blender MCP и расходует кредиты без контроля каждой генерации. Работаем вручную: промпт из Claude → сайт Tripo → скачали → импорт в Blender/Unity. Вернуться к вопросу, если ручной процесс станет узким местом.

Полки и стеллажи делать префабами с точками спавна внутри.

## Уровни качества карты (предложено)
1. **Демо:** примитивы и ProBuilder с фасками, цветной запечённый свет, bloom, графичные узоры на полу и стенах (плитка кухни, паркет, обои). Узоры генерировать скриптом (процедурно или Python), это не ИИ-контент.
2. **После подтверждения механики:** предметы из CC0-наборов и Tripo, модули со скруглёнными фасками через Blender (Bevel, Subdivision).
3. **Перед релизом:** художник на ключевые элементы (вывеска, узор пола, главные предметы, декор).
Переход на следующий уровень решается по результатам тестовой комнаты (`style-test-room.md`).

## Как скрыть, что база собрана из примитивов (предложено)
Задача: архитектура (стены, пол, потолок, стойки, полки) не должна выглядеть как набор коробок. Предметы для маскировки идут из Tripo, база строится кодом.
1. **Скругление всех рёбер.** Единая фаска ~2–4 см на всех деталях (ProBuilder Bevel, свой генератор «rounded box» в Editor-скрипте или Bevel в Blender). Острые углы 90° — главный признак примитива.
2. **Молдинги и обвязка:** плинтусы, карнизы, дверные и оконные рамы, панели на стенах, обшивка барной стойки, кромки полок, колонны.
3. **Разные формы:** скруглённая барная стойка, арки, круглые колонны и столы, потолочные балки.
4. **Вариативность:** мебель разной высоты и цвета, лёгкая асимметрия, нерегулярные промежутки. Повторяющиеся идентичные модули выдают сборку.
5. **Не плоские цвета:** лёгкий градиент по высоте, вертексные цвета, узоры, декали (меню на стене, плакаты, разметка, таблички).
6. **Свет добавляет глубину:** запечённый AO и отражённый свет, цветные источники, emissive-лампы и вывески.
7. **Единый язык с Tripo-предметами:** одинаковая палитра, тот же шейдер и сопоставимая «пухлость» скруглений.
8. **Мелкая детализация:** растения, вешалки, таблички. Только статичный декор, не вселяемый и не сбивающий игру на несоответствиях.
