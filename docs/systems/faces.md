# Живые 2D-лица на предметах

**Статус: решено, не запасной вариант — вторая фирменная фишка игры наравне с тараном/пинком** (`ram-kick.md`). Изначально была помечена как запасной вариант (см. историю в `parked.md`), статус изменён.

## Суть
На каждом предмете (и вселённом, и обычном декоративном) есть 2D-лицо. Оно «живое»: зрачки следят за охотником, а базовое выражение меняется по игровым событиям (например, оглушение после пинка). Добавляет клипабельности без влияния на баланс.

## Критическое правило: одинаково для всех предметов, вне зависимости от того, спрятан ли там игрок
Система работает **фоново для всей карты**, не только для предметов, в которых кто-то вселился. Если бы поведение лица отличалось у занятых и пустых предметов, это была бы новая утечка информации, выдающая игрока — то, с чем мы уже боролись отдельно для освещения (`art-and-audio.md`, единое освещение вселённых и обычных предметов через Light Probes). Правило распространяется и сюда.

## Архитектура (два слоя, оба дёшевы технически)

### Слой 1 — базовое выражение (смена текстуры)
- Лицо — PNG с альфа-каналом (прозрачный фон), наклеен как маленький Quad-декаль поверх предмета, unlit-прозрачный материал.
- «Выражения» = разные PNG-картинки, переключаемые скриптом по событиям. Не покадровая анимация, а смена спрайта.
- **Обязательные состояния для старта:**
  - Обычное (по умолчанию)
  - Оглушение после пинка (`ram-kick.md`) — включается с момента, когда предмет физически осел (начало "фазы в отключке"), держится весь остаток таймера оглушения вместе со звёздочками над головой, выключается в момент начала самовыравнивания. Точная последовательность — в `ram-kick.md`.
- **Кандидат на будущее (не обязательно сейчас):** испуг в момент поимки («пуфф»).
- **Явно НЕ привязывать к near-miss** (`hunter-combat.md`): near-miss специально спроектирован как скрытая информация, видимая только задетому прячущемуся. Реакция лица на near-miss была бы видна и охотнику тоже — это утечка информации, ломающая замысел near-miss. Не реализовывать.

### Слой 2 — поворот всего лица навстречу охотнику (решено: главный механизм, не зрачки отдельно)
**Приём: ограниченный поворот навстречу («constrained look-at»), как башня танка.** Лицо не жёстко приклеено к поверхности, а может довернуться в сторону охотника в пределах ограниченного угла — не свободный billboard (иначе будет визуально «отклеиваться» от предмета), а зажатый конус поворота.

- Скрипт вычисляет направление на охотника от точки крепления лица (`FaceAnchor`).
- Целевой поворот decal-плоскости доворачивается к этому направлению, но **угол зажат** (предложено ±25-35° от базовой ориентации, калибровать по форме предметов) — если охотник вне этого конуса (например, стоит слишком близко сбоку), лицо держится на максимальном угле, не пытаясь довернуться дальше.
- **Эффект именно тот, что нужен:** охотник смотрит на стакан сверху вниз → вектор на охотника направлен вверх → лицо наклоняется по тангажу (pitch) вверх и «приподнимается», обращаясь к охотнику. Охотник подходит сбоку → доворот по рысканью (yaw).
- **Плавность движения — Slerp** (сферическая интерполяция поворота), тот же приём, что уже используется для самовыравнивания предмета после пинка (`ram-kick.md`) — лицо доворачивается за несколько кадров, не щёлкает мгновенно.
- Работает только когда охотник в пределах радиуса реакции (**предложено ~8-10 м, калибровать**), иначе лицо держит нейтральную базовую ориентацию.

### Слой 3 — зрачки (докрутка поверх общего поворота лица)
- Зрачки — отдельный маленький дочерний слой поверх базового лица (не часть картинки выражения), даёт финальную «докрутку» взгляда уже после того, как всё лицо довернулось по слою 2.
- Смещение зрачков ограничено небольшим радиусом («глазница»).
- Дополнительный, необязательный для первой версии слой — можно добавить после проверки, что сам поворот лица (слой 2) уже работает и выглядит живо.

## Подготовка предмета (ручная работа, часть приёма ассета)
Каждый префаб предмета получает пустой объект-якорь («FaceAnchor»): позиция + поворот, задающие, где на этом конкретном предмете сидит лицо. Это разовая ручная разметка на каждый префаб, не автоматизируется полностью (форма предметов разная). Добавить в чек-лист приёма ассета (`art-pipeline.md`).

## Что готовит владелец проекта (не Claude Code — это ручной творческий шаг)

**Формат:** PNG с прозрачным фоном (альфа-канал), единый размер холста для всех лиц (например, 512×512, чтобы масштаб был предсказуем на всех предметах), один и тот же стилевой блок в промпте для всех генераций (единый стиль серии).

**Критично: нейтральное/базовое лицо рисуется БЕЗ зрачков** (белки глаз, веки, форма глаза — зрачок оставлен пустым/прозрачным местом). Зрачок — отдельный универсальный маленький спрайт (кружок), один на все предметы, накладывается и двигается кодом. Если зрачок нарисован прямо на общей картинке, отдельно двигать его нельзя.

**Метаданные для каждого базового (idle) лица:** координаты центра и радиус движения для левого и правого глаза (например, «левый глаз: x=180, y=210, радиус 25px») — простой текстовый список рядом с файлом, чтобы код знал, куда накладывать и в каких пределах двигать зрачок. Без этого шага докрутка взгляда невозможна технически.

**Выражения на события (например, оглушение):** можно рисовать полностью готовыми, с уже "зашитыми" глазами (спираль, зажмурено и т. п.) — координаты не нужны, слежение взглядом на этих кадрах отключается, показывается статичная картинка целиком.

**Минимальный комплект на один предмет:** `<prop>_face_idle.png` (+ координаты глаз) и `<prop>_face_stunned.png`. Зрачок один универсальный на всю игру, не per-предмет.

**Не входит в задачу владельца:** кадры анимации, спрайт-листы, покадровая последовательность — поворот лица, докрутка взгляда, плавность (Slerp) делает код.

## Генерация лиц (ИИ, ведёт лично владелец проекта)
- Лица генерируются нейросетью владельцем проекта лично, учёт — в `assets-licenses.md` (уже решено: ведёт лично владелец, не агент).
- **Для единого стиля всех лиц** нужен общий «стилевой блок» в промпте, как у 3D-моделей (`art-pipeline.md`), иначе разные лица будут выглядеть как из разных наборов. Конкретный текст блока — на усмотрение владельца при генерации, главное — использовать один и тот же блок для всех генераций лиц.
- Формат: PNG с прозрачным фоном (альфа-канал), не просто квадратное изображение.

## Порядок реализации для Claude Code (решено)
1. **Один тестовый предмет сначала**, не вся карта сразу (например, стакан) — вся система проверяется на нём, прежде чем тиражировать.
2. **Компоненты:**
   - `FaceController` — держит ссылку на `FaceAnchor`, переключает выражение (idle/stunned), считает поворот-навстречу (look-at с зажатым углом + Slerp, Слой 2).
   - `PupilController` — дочерний слой, смещает зрачок в пределах радиуса глазницы (координаты из подготовленных метаданных), докручивает взгляд поверх общего поворота (Слой 3).
   - `StarEffect` — вращение дочернего объекта со спрайтами звёзд вокруг вертикальной оси, включается/выключается сигналом из фазы "в отключке" (`ram-kick.md`).
3. **Точки интеграции:** сигнал начала/конца фазы "в отключке" → переключает выражение и звёзды; радиус реакции (~8-10 м) и максимальный угол поворота (~±25-35°) — параметры, не зашиты жёстко, для последующей калибровки; `FaceController` не должен знать, вселился ли в предмет игрок — только положение охотника (ключевое правило выше).
4. **Проверка:** скриншоты сцены (MCP for Unity) с тестовым предметом при разных положениях охотника (сбоку/снизу/сверху) — визуальная проверка правдоподобия поворота, зрачка в пределах глазницы, срабатывания звёзд.
5. **Тиражирование** на остальные предметы пула (`spawn.md`) только после проверки на тестовом.

## Оптимизация (для performance.md)
Поворот лица (Slerp каждый кадр) дороже плоской смены текстуры, но всё ещё дёшево на масштабах "несколько предметов рядом с охотником одновременно". При большом числе предметов с активным слежением — накопительная нагрузка. Решение по аналогии с ботами (`bots.md`, пониженный тик вдали от угрозы): пересчитывать поворот только для предметов в пределах радиуса реакции от охотника, не для всей карты сразу. Добавить как переключаемый пункт в таблицу настроек качества (`performance.md`): на низком уровне качества — лица либо полностью выключены (чисто декоративная система, не влияет на геймплей), либо без поворота/зрачков (статичное выражение, только смена текстуры по событиям).

## Открыто
- Финальный радиус реакции (предложено ~8-10 м) и максимальный угол поворота (предложено ±25-35°) — калибровать по форме предметов, чтобы не выглядело сломанно.
- Финальный стилевой блок промпта для генерации лиц.
- Скорость Slerp-доворота (насколько быстро лицо "замечает" охотника).
- Входит ли в объём демо Next Fest или добавляется после MVP (см. `demo-scope.md`).
