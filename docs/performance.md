# Оптимизация (закладывать с начала)

**Рендеринг:** baked lighting, unlit/toon шейдеры, GPU instancing для однотипных предметов, текстурные атласы, LOD, frustum/occlusion culling.
**CPU:** object pooling для предметов при респавне и замене.
**Сеть:** частота синхронизации Fusion без лишних данных.

**Целевая планка (уточнено):** ориентир — минимальные требования Meccha Chameleon (Win10/11 64-bit, CPU уровня i3, RAM 4 ГБ, любая DirectX 11 видеокарта, ~3 ГБ места, данные с неофициального зеркала, не проверены на официальной странице Steam). Она построена на Unreal Engine 5, но геометрия и сцены простые.

**Честная оценка:** совпасть с i3/4 ГБ нереалистично — у нас больше систем одновременно: сетевой код Fusion (клиент+сервер на машине хоста), физика ragdoll, пространственный звук с raycast-окклюзией через стены (`beacon.md`), bloom и цветной свет (`art-and-audio.md`), процедурная анимация движения предметов, боты. Каждая по отдельности лёгкая, но вместе на слабом CPU/GPU могут просесть по кадрам, особенно у хоста, который держит на себе и сервер, и рендер.

**Реалистичный целевой ориентир:** CPU уровня i5 (4 ядра+), RAM 6-8 ГБ, любая DirectX 11 видеокарта, ~3-4 ГБ места. Это на класс выше Meccha Chameleon, но близко, и совпадает с вашим собственным железом (i5-4460, 8 ГБ) — то есть ваша машина должна тянуть игру на минимальных настройках.

**Как приблизиться к более низким требованиям (рычаги на будущее, не для MVP):**
- Настройки качества: выключаемый bloom, упрощённая occlusion-проверка звука, лимит числа предметов с процедурной анимацией одновременно.
- Отдельный «облегчённый» режим тарана/ragdoll с меньшим числом активных физических тел (уже заложен лимит в резервных рычагах ниже).
- Финальную проверку делать на реальном железе уровня минимальных требований, а не только на машине разработчика.

**Резервные рычаги** (применять по данным Unity Profiler, не гадать заранее):
- лимит одновременных физических объектов (ragdoll/Rigidbody) с упрощённым фолбэком сверх лимита;
- более агрессивные LOD/occlusion, меньшее разрешение атласов;
- настройки качества на стороне игрока (разрешение рендера, тени, дальность прорисовки).


## Как облегчить требования дальше (уточнено с владельцем)
**Важное уточнение:** у предметов нет общей физики. Физика есть только у игроков (движение) и точечно: ragdoll при таране (`ram-kick.md`), импульс + оглушение при пинке маленького предмета. Покачивание вселённого предмета при движении — это визуальная анимация трансформа (`movement-and-camera.md`), не физика, и считается только для предмета, которым в этот момент управляет игрок, — само по себе уже дёшево.

### 1. Настройки качества с уровнями (самый большой и дешёвый выигрыш)
Одна из причин, почему высокие требования — не сама графика, а то, что все эффекты включены всегда. Решение: три уровня (Низкий/Средний/Высокий), выбираются в меню, по умолчанию — автоопределение по железу.

| Система | Низкий | Средний | Высокий |
|---|---|---|---|
| Bloom | выкл | слабый | как в `art-and-audio.md` |
| Тени | простые/запечённые (единые для всех предметов, вселённых и нет — см. правило неразличимости в `art-and-audio.md`) | то же | то же |
| Окклюзия звука через стены | простая (по расстоянию, без raycast) | raycast раз в 0,2 сек | raycast каждый выстрел |
| Дальность прорисовки / LOD | агрессивный LOD, меньше радиус | средний | полный |
| Разрешение рендера | масштабирование вниз (~75%) | 100% | 100%+ |
| Частица пыли (ускорение, приземление) | выкл | упрощённая (меньше частиц) | полная |
| Текстуры | половина атласа | полное | полное |

Это единственный пункт, который напрямую двигает нижнюю границу требований, не трогая геймплей.

### 2. «Далеко от игроков» — не актуально в нашем случае
Идея снижать детализацию для того, что «никто не видит», обычно экономит на физике/анимации фоновых объектов — но у нас таких затрат и так нет (см. уточнение выше). Единственное похожее место — **тик ботов-прячущихся вдали от угрозы** (решено, см. пункт 3).

### 3. Боты: реже «думают» вдали от угрозы (решено)
Применяется **только к ботам-прячущимся** (боты-охотники отложены, `bots.md`). Бот, который далеко от охотника, пересчитывает решения реже (например, раз в 0,3 сек вместо каждого кадра); при приближении угрозы — чаще. Поведение не меняется, экономится только частота пересчёта. Важно: это НЕ влияет на «интересность» ботов — она определяется логикой состояний и балансом (`bots.md`), а не частотой тика; при приближении охотника бот всегда реагирует в полную силу.

### 4. Хост — главное узкое место, не рендер
У хоста на одной машине одновременно сервер и клиент. Смягчения:
- **Fixed tick rate пониже**, если Fusion позволяет гибко настраивать частоту симуляции — на low-tier железе используем меньший tick rate, чем на высоком.
- Область интереса (interest management) — синхронизировать детальные данные только для объектов рядом с каждым клиентом, а не всей карты сразу (снижает CPU-нагрузку на хосте с ростом числа игроков).
- Ограничить максимум игроков на этапе демо (например, 8-10), а не сразу целиться в 24, как у референсов с UE5-командой.

### 5. Физика (ragdoll) — структурно дороже всего
- **Упрощённый ragdoll (решено):** 6-8 физических тел (голова, туловище, 2 руки, 2 ноги) вместо полного гуманоидного рига (15+). Точное повторение реалистичного падения не нужно — важна только смешная картинка, поэтому это не временная оптимизация, а финальное архитектурное решение (`ram-kick.md`).
- **Лимит одновременных активных ragdoll: 3** (решено, по факту игры одновременно больше и не бывает — таран требует полной шкалы ускорения, поэтому естественный поток событий и так редкий). Лимит нужен только как страховка на крайний случай, не как обычный режим работы.
- Предметы, в которые не вселились, — статичная геометрия без Rigidbody, не участвуют в физике вообще, пока не заняты игроком (снижает число активных физических тел на порядок).

### 6. Рендер — стандартные, но обязательные приёмы
- GPU instancing для одинаковых предметов (банки, коробки), текстурные атласы, агрессивный LOD и occlusion culling — уже в списке выше, но именно они дают основной выигрыш на слабых GPU.
- Запечённый свет вместо реального — самый дешёвый способ получить красивую картинку без нагрузки на GPU (совпадает с решением в `art-and-audio.md`).
- Один draw call на материал где возможно (SRP Batching в URP).

### 7. Память
- Object pooling для предметов (уже вселяемых объектов при респавне), эффектов пыли и звуковых источников — пул, а не Instantiate/Destroy на каждое событие. Пыль от ускорения и «пуфф» уже 2D-спрайты (решено), это и так дёшево.
- Компрессия текстур, не хранить полноразмерные текстуры для мелких предметов.
- Аудиофайлы в сжатом формате, не WAV.

### 8. Процесс
- Профилировать с первой недели, не в конце: Unity Profiler на слабой конфигурации (ваша машина как раз ориентир) — это дешевле, чем находить проблему в декабре.
- Целевой FPS для минимальных настроек: 30, а не 60 — снижает требования сразу почти вдвое для GPU-части.
- **IL2CPP + code stripping (техническая настройка сборки, решение за Claude Code, не требует вашего решения):** финальный билд легче для CPU и меньше по размеру, никак не меняет геймплей — применяется как стандартная практика перед релизом.
- **Одна сцена без стриминга (уточнение, не пункт оптимизации):** у нас нет системы «уровней» — карта одна, всегда загружена целиком, поэтому накладные расходы на подгрузку контента на лету (Addressables/streaming), которые есть у игр с несколькими уровнями, у нас просто отсутствуют — экономить тут не на чем, это не наша архитектура.
- **NavMesh для ботов:** карта одна, не очень большая, одноуровневая — сложная многоуровневая навигация не нужна, простой плоский NavMesh дешевле в расчёте. Не влияет на «интересность» ботов (это решает `bots.md`), только на то, сколько стоит пересчёт пути.


## Предполагаемые системные требования (оценка, не измерение)
Появятся официально только после профилирования на реальном железе (первая проверка — на машине разработчика, i5-4460 / 8 ГБ, см. `business.md`). Пока это расчётная прикидка по плану систем.

| | Минимальные | Рекомендуемые |
|---|---|---|
| ОС | Windows 10/11 64-bit | Windows 10/11 64-bit |
| CPU | 4-ядерный ~3,2 ГГц (уровень i5-4460 / Ryzen 3 1200) | 4+ ядра ~3,6 ГГц (уровень i5-8400 / Ryzen 5 2600) |
| RAM | 8 ГБ | 12-16 ГБ |
| GPU | Любая DirectX 11, 2 ГБ видеопамяти (GTX 750 Ti / RX 560 уровня) | GTX 1050 Ti / RX 570 уровня или выше |
| Место на диске | ~4-5 ГБ | ~5 ГБ (SSD для быстрой загрузки) |
| Сеть | Стабильный интернет (важно для хоста, `networking.md`) | Стабильный широкополосный интернет |

**Почему выше, чем у Meccha Chameleon (i3/4 ГБ):** у неё одна механика на UE5 с простыми сценами; у нас параллельно работают сеть (Fusion, хост = сервер + клиент), физика (ragdoll, предметы), пространственный звук с проверкой стен, bloom и цветной свет, боты. Минимальные требования ориентированы на настройки «низкий уровень качества» из раздела выше.

**Статус:** прикидка для планирования, не финальная цифра для страницы Steam. Уточняется по мере профилирования на этапах MVP и тестовой комнаты.
