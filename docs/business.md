# Бюджет, железо, стратегия ИИ (для человека, агенту читать не нужно)

## Бюджет (оценка, не гарантия)
**Текущее решение — только подписка Claude Pro ($20/мес), без API.** Остальные статьи: Tripo $20-40, Steam Direct $100, звук $0-30, буфер $50-100. Photon Fusion free tier, Unity, Quaternius $0. Итого без учёта ИИ ориентировочно $170-270 до релиза.
Лимиты Pro общие для Claude и Claude Code (сессия 5 часов + недельный). Если лимитов Pro не хватит на фазу активной разработки, следующий шаг — Max (не API), это не входит в решение «без API-ключа».
**Если решение изменится и понадобится Opus по API** (сейчас не планируется): ориентировочно ещё $200-350 до Next Fest, $300-500 до релиза; тогда обязателен spend cap в Anthropic Console и осторожность с `ANTHROPIC_API_KEY` (см. ниже).

## Стратегия моделей (решено: пока только подписка Claude Pro, без API-ключа)
Sonnet ~85%: управление, превращение, спавн, UI, лобби, оптимизация, локализация. Opus ~15% через саму подписку (переключение модели в Claude Code), а не через API — пока используем только Pro. Haiku 4.5 для простых задач.
**Важно:** пока работаем только на подписке, не задавайте переменную окружения `ANTHROPIC_API_KEY` — если она есть в системе, Claude Code начнёт использовать платный API вместо подписки. Если позже перейдёте на API для Opus, тогда и понадобится spend cap в Anthropic Console (Settings → Limits → Set monthly limit) — не раньше.
Экономия лимита подписки: короткие сессии, этот набор файлов вместо пересказа, thinking только для архитектурных решений, начинать новую сессию при разрастании контекста.

## Железо
i5-4460, 8 ГБ DDR3, RX 580 4 ГБ. Решено: работаем на этом железе без апгрейда.
**Риск (принят):** тест мультиплеера с 2-4 клиентами Unity одновременно на 8 ГБ будет тяжёлым, возможны подвисания при сборке. Смягчение: закрывать лишние программы на время тестов, тестировать по 1-2 клиента на этой машине и добирать до 4 клиентов через друзей/Discord вместо параллельного запуска всех на одном ПК.

## Оптимизация самого редактора Unity (для комфортной разработки на этом железе)
Отдельно от игровой оптимизации (`performance.md` — это про готовую игру для игроков). Приоритет по эффекту:
1. **Исключить папку проекта (`Library`, `Temp`, `obj`) и папку установки Unity из антивируса/Defender** — обычно самый большой выигрыш в скорости компиляции/импорта.
2. **Enter Play Mode Options** (`Project Settings → Editor`): включить, отключить Reload Domain и Reload Scene — почти мгновенный запуск Play вместо полной пересборки каждый раз. Нюанс: статические переменные не сбрасываются между запусками, учитывать при написании кода.
3. При установке через Hub — ставить только Windows Build Support, без Android/iOS/WebGL/Linux/Mac/документации/языковых пакетов.
4. Ставить только реально нужные пакеты (ProBuilder, AI Navigation, Cinemachine, Input System, Fusion), не добавлять лишнее «про запас».
5. В Scene View на время активной работы отключать Realtime GI preview, снижать качество теней окна редактора.
6. Не держать открытым Profiler/Package Manager/Asset Store без необходимости.
**Диск:** если SSD ещё нет — переход на него, скорее всего, даст больше, чем все пункты выше вместе взятые.

## Управление местом на диске (решено: 39 ГБ свободно на SSD, освободить больше нельзя)
- **На SSD остаётся:** Unity Editor, активная папка проекта (`Assets`, `Library`, `Temp`, `.git`), Blender.
- **На HDD (если есть) — не критично к скорости:** готовые тестовые билды, сырые скачанные паки ассетов до распаковки, сырые экспорты из Tripo до чистки в Blender, резервные копии.
- Переносить весь проект/Unity Editor целиком на HDD не рекомендуется: компиляция/импорт станут заметно медленнее на и так не самом мощном CPU.
- Если появится возможность — недорогой внешний SSD (USB 3.0) снял бы вопрос места полностью.
- Практика: удалять старые тестовые билды после проверки; при разрастании `Library` можно безопасно удалить (перегенерируется); проверять свободное место раз в 2-3 недели.
